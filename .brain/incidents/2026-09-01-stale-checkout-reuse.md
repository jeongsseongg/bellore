# 다른 상품 미결제 주문 재사용 — 2026-09-01

## 사용자 영향

- 현재 상품과 금액이 다른 이전 미결제 주문의 상태가 새 체크아웃 위에 표시돼, 결제를 시작하지 않았는데도 `결제 취소 확인 중` 안내가 나타났다.

## 확인된 원인

- 결제 요청 응답 복구가 `recoveryOnly` 주문의 상품·금액을 현재 체크아웃과 대조하지 않고 이전 주문을 서버 확인 경로로 넘겼다.
- 운영 실측에서 화면 상품·금액과 DB 주문 상품·금액이 달랐고, 공급자 상태는 `READY`, `payment_key`와 `paid_at`은 null이었다. 따라서 가맹점 승인 실패나 실제 청구가 아니라 이전 주문 재사용이 원인이었다.

## 복구 원칙

- 이전 주문과 현재 상품 또는 금액이 다르면 그 사실을 별도로 전달한다.
- 서버는 사용자가 결제창을 떠난 주문 중 공급자 상태가 정확히 `READY`인 경우만 기존 미결제 종료 RPC로 정리한다.
- `PENDING`, `PAY_PENDING`, 가상계좌 발급, `PAID` 상태는 자동 종료하지 않으며, 복구 경로에서 PortOne 결제창을 다시 열지 않는다.
- 결제사 응답은 공개 코드와 HTTP 상태만 구조화해 기록하고 원문 오류 객체는 노출하지 않는다.
