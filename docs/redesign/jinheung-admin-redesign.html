앞선 두 시안은 골격을 그대로 둔 채 껍데기만 바꿨습니다. 사이드바에 대시보드, 메뉴는 시스템 모양 그대로. 이번에는 구조부터 다시 짭니다. 메뉴를 하루 순서로 바꾸고, 화면을 휴대폰 기준으로 다시 그리고, 화면에서 색을 전부 걷어낸 뒤 꽃에게만 돌려줍니다.

01 진단

껍데기가 아니라 골격이 문제였습니다

색과 모서리를 두 번 바꿨는데도 "옛날 어드민" 느낌이 남았던 이유입니다.

골격 01

메뉴가 시스템 모양대로 되어 있습니다

상품 관리 · 주문 관리 · 고객 관리 · 설정. 이건 데이터베이스 테이블 이름이지 사장님이 하루를 보내는 순서가 아닙니다.

→ 하루 순서로 다시 짭니다 (2번)
골격 02

데스크톱을 기준으로 그렸습니다

사장님은 사무실 책상이 아니라 작업장에서 휴대폰으로 봅니다. 새벽에 주문이 들어오고, 손에는 꽃이 들려 있습니다.

→ 휴대폰이 기본, 데스크톱은 같은 시스템의 넓은 판
골격 03

대시보드가 일을 안 합니다

0·0·0·70 네 숫자를 보고 스스로 해석해야 합니다. 숫자는 상태일 뿐 다음 행동이 아닙니다.

→ 숫자 대신 오늘 할 일 흐름을 첫 화면에
골격 04

70개 상품이 전부 똑같이 생겼습니다

파는 물건이 색으로 구분되는 조화인데, 화면에서는 회색 글자 줄로만 보입니다. 색상은 "노랑, 보라, 빨강" 글자로 적혀 있습니다.

→ 상품 색이 곧 화면의 색. 유일한 컬러 (3번)
골격 05

재고 70개를 하나씩 고쳐야 합니다

모든 상품 재고가 0인데, 채우려면 수정 버튼을 70번 눌러야 합니다. 현실적으로 불가능합니다.

→ 재고 한 번에 넣기 전용 화면 (5-4)
골격 06

남의 옷을 입었습니다

토스는 은행 앱이라 파랑입니다. 진흥몰은 꽃 도매상입니다. 남의 색을 쓰면 어디서 본 듯한 화면이 됩니다.

→ 먹색 UI + 꽃 색 데이터. 진흥몰만의 규칙
02 구조

메뉴를 하루 순서로

이 개편에서 가장 중요한 변화입니다. 색보다 이게 먼저입니다.

지금 — 시스템 순서
  1. 01상품 관리 테이블 이름
  2. 02주문 관리 테이블 이름
  3. 03고객 관리 테이블 이름
  4. 04주문·입금 설정 거의 안 씀
  5. 05계정 보안 1년에 한 번
→
개편 — 하루 순서
  1. 01오늘 지금 할 일
  2. 02주문 하루 수십 번
  3. 03상품 재고·가격
  4. 04더보기 고객·설정·보안

왜 4개인가

  • 휴대폰 하단 탭은 4개가 한계입니다. 5개가 넘으면 글자가 작아지고 오누름이 생깁니다.
  • 「오늘」이 새로 생긴 첫 화면입니다. 켜자마자 "지금 뭘 해야 하는지"가 보입니다.
  • 고객 관리·설정·보안은 매일 쓰지 않으므로 「더보기」로 내립니다. 자리를 차지할 이유가 없습니다.
  • 데스크톱에서는 같은 4개를 왼쪽 세로 메뉴로 폅니다. 구조가 같아야 기기를 바꿔도 헷갈리지 않습니다.
03 정체성

색은 꽃에게만 줍니다

이 규칙 하나가 진흥몰을 다른 쇼핑몰과 구분 짓습니다.

화면 구성요소 — 버튼, 메뉴, 카드, 배경 — 은 전부 먹색과 종이색입니다. 컬러가 없습니다. 그래서 화면에 색이 나타나면 그건 반드시 꽃입니다. 상품 색상, 재고 막대, 분류 표시가 전부 실제 조화의 색을 그대로 씁니다. 70개 상품이 글자를 읽지 않아도 구분됩니다.

예외는 하나뿐입니다. 조치가 필요할 때의 빨강 #C8342B. 화면에 빨강이 보이면 사장님이 지금 뭔가 해야 한다는 뜻입니다. 다른 데 쓰지 않기 때문에 눈에 즉시 들어옵니다.

쓰임색규칙
UI 전부#121417 먹글자·버튼·테두리·아이콘. 버튼은 검정 채움, 보조는 검정 테두리.
바탕#EFEFEB 종이흰색이 아니라 아주 옅은 회색. 종이 느낌이 나고 흰 면이 떠 보입니다.
조치 신호#C8342B 빨강지금 할 일에만. 미확인 주문, 품절, 빈 필수값. 그 외 절대 금지.
상품 색 실제 조화 색. DB의 색상값에서 그대로 가져옵니다. UI에는 쓰지 않습니다.

글자와 숫자

  • Pretendard · 제목은 800 굵기에 자간 -0.05em까지 좁힙니다. 확신 있는 인상을 만듭니다.
  • 숫자·상품코드·수량은 등폭 글꼴(ui-monospace). 도매 장부처럼 세로로 딱 맞게 떨어집니다. 2,000원과 12,000원의 자릿수가 눈으로 비교됩니다.
  • 모서리는 각지게(0px). 둥근 모서리를 쓰지 않습니다 — 그게 토스와 갈리는 지점이자, 종이·인쇄물 느낌을 만드는 부분입니다.
이건 취향이 아니라 기능입니다. 크림색 조화와 흰색 조화는 글자로는 구분이 안 되지만 와 를 나란히 두면 즉시 구분됩니다. 색이 정보인 업종에서 색을 회색으로 눌러버리면 가장 중요한 정보를 버리는 것입니다.

개발 지시

  • 「오늘」은 새로 만드는 화면입니다. 규칙 3개로 목록을 만듭니다 — 재고 0인 상품 수, 계좌 3필드 중 빈 값, 이름 없는 고객 수. 전부 해결되면 흐름 카드가 사라지고 오늘의 매출이 그 자리에 들어옵니다.
  • 흐름의 지금 할 일 하나만 빨간 번호, 끝난 건 검정 체크, 아직 먼 건 흐리게. 어디부터 손댈지 고민이 없습니다.
  • 재고 한 번에 넣기가 이번 개편에서 실질적으로 가장 큰 기능 추가입니다. − / + 는 46×46px, 숫자를 직접 탭하면 키패드가 뜨고, 하단 저장 바는 항상 붙어 있습니다.
  • 주문 행의 오른쪽 버튼은 상태에 따라 하나만 — 입금 대기 → 「입금 확인」(검정 채움), 배송 준비 → 「운송장」(테두리), 완료 → 없음.

지금
  • 색상이 "노랑, 보라, 빨강, 크림" 글자로 적혀 있음
  • 70개가 전부 같은 회색 줄

개편

  • 재고 0 → 자동 품절, 빨강은 여기만

08 순서

작업 순서

1~3번이 이번 개편의 핵심입니다. 나머지는 이 셋을 따라옵니다.

  1. 메뉴를 4개로 다시 짠다오늘 · 주문 · 상품 · 더보기. 휴대폰은 하단 탭, 데스크톱은 왼쪽 세로. 가장 중요한 변화입니다.
  2. 「오늘」 화면을 새로 만든다규칙 3개(재고 0 / 계좌 빈값 / 이름 없는 고객)로 할 일 흐름을 만듭니다. 전부 해결되면 매출 화면으로 바뀝니다.
  3. 「재고 한 번에 넣기」를 만든다70개를 하나씩 여는 건 불가능합니다. 이게 없으면 진흥몰은 열 수 없습니다.
  4. 색상 문자열을 색상코드 표로 바꾼다"노랑"→#E0A81A 매핑 표를 만들고 DB 색상값을 여기에 연결합니다. 색 띠·점·막대가 전부 여기서 나옵니다.
  5. 토큰 CSS를 전역에 넣는다4번 블록 복사. 모든 border-radius를 0으로 바꿉니다.
  6. UI에서 컬러를 전부 걷어낸다파랑·초록 버튼을 검정으로. 빨강은 조치가 필요한 곳에만 남깁니다.
  7. 숫자에 등폭 글꼴을 건다금액·수량·상품코드 전부. tabular-nums도 함께.
  8. 상태를 계산값으로 바꾼다재고 0 → 자동 품절. "0단인데 판매중"이 구조적으로 나올 수 없게.
  9. Pretendard를 서버에 올린다CDN 금지. letter-spacing:-.02em, word-break:keep-all 함께.
  10. 문구를 해요체 + 「단」 단위로 고친다6번 표 그대로.
하지 말 것 — ① 메뉴를 5개 이상으로 늘리기 ② UI에 컬러 다시 넣기(파랑 버튼, 초록 배지) ③ 꽃 색을 회색으로 눌러 통일하기 ④ 둥근 모서리 되살리기 ⑤ 데스크톱 폭이 남는다고 메뉴 늘리기 ⑥ 상품코드 체계·단·부쉬 단위 건드리기.
