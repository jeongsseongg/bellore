현재 진흥몰 관리자 콘솔은 왼쪽 메뉴와 상단 탭이 같은 항목을 두 번 그리고, 화면 오른쪽 절반이 비어 있으며, 글자와 버튼이 작습니다. 이 문서는 원티드(Wanted)의 밝고 넓은 레이아웃과 토스의 세그먼트 전환을 기준으로 9개 화면을 다시 설계하고, 개발자가 그대로 따라 만들 수 있도록 토큰·컴포넌트·화면별 지시를 담았습니다.

이 문서 읽는 법

구현하는 사람은 3·4번(토큰·컴포넌트)만 먼저 만들면 나머지는 조립입니다.

  • 1번 — 지금 무엇이 왜 문제인지. 캡처에서 확인된 것만 적었습니다.
  • 2번 — 개편 원칙 5가지. 판단이 갈릴 때 여기로 돌아옵니다.
  • 3번 — 디자인 토큰. CSS를 그대로 복사해서 쓰면 됩니다.
  • 4번 — 공통 컴포넌트 7종. 세그먼트는 실제로 눌러볼 수 있습니다.
  • 5번 — 화면 9개. 각각 지금 문제 → 개편 목업 → 개발 지시 순서입니다.
  • 6~8번 — 접근성 규칙, 반응형, 작업 순서 체크리스트.
목업은 그림이 아니라 실제 HTML입니다. 브라우저에서 이 문서를 열고 우클릭 → 검사로 어떤 CSS가 걸려 있는지 바로 확인할 수 있습니다. 상단의 글자 크게 버튼을 누르면 나이 배려 모드에서 레이아웃이 어떻게 버티는지도 볼 수 있습니다.
01

지금 무엇이 문제인가

보내주신 캡처 9장에서 확인된 것만 적었습니다. 취향 문제가 아니라 대부분 구조 문제입니다.

구조

같은 메뉴를 두 번 그린다

왼쪽 사이드바 5개(상품 관리·주문 관리·고객 관리·주문·입금 설정·계정 보안)와 상단 탭 5개가 완전히 동일합니다. 지금 어디에 있는지 표시도 두 군데에서 따로 납니다.

→ 사이드바만 남기고 상단 탭은 삭제. 세그먼트는 화면 안쪽 필터로만 씁니다.
레이아웃

오른쪽 절반이 비어 있다

고객 관리·계정 보안 화면에서 내용이 왼쪽에만 몰려 있고 오른쪽은 흰 여백입니다. 넓은 모니터일수록 더 심해집니다.

→ 콘텐츠 폭을 최대 1280px로 잡고 남는 공간은 2단 배치로 채웁니다.
데이터

고객 이름이 ??? ???

고객 관리에서 이름이 물음표로 깨져 나옵니다. 한글 인코딩이 UTF-8이 아니거나, 이름이 없는데 빈 값 처리를 안 한 경우입니다.

→ 응답 UTF-8 확인 + 이름 없으면 이메일 앞부분으로 대체하고 "이름 미등록" 배지를 답니다.
모순

재고 0개인데 "판매중"

상품 관리 70개 전부 0개 · 판매중입니다. 고객이 주문할 수 있는데 보낼 물건이 없다는 뜻입니다.

→ 재고 0이면 자동으로 품절 배지. 상태 규칙표는 5-2에 있습니다.
가독성

글자와 버튼이 작다

상품 행의 코드·색상 줄, 폼 라벨, "수정" 버튼이 모두 12~13px대입니다. 나이 드신 분이 쓰기 어렵고, 마우스로 정확히 누르기도 힘듭니다.

→ 본문 17px, 라벨 15px, 버튼 높이 56px, 누르는 영역 최소 48px.
정보

숫자 4개가 전부 0인데 크게 보인다

운영 현황 KPI가 0·0·0·70입니다. 지금 할 일이 없다는 뜻인데 화면에서 가장 크게 강조돼 있습니다.

→ 0은 회색으로 눌러 쓰고, 조치가 필요한 값만 색과 바로가기를 답니다.
폼

설정이 한 화면에 쏟아진다

주문·입금 설정에 주문 운영 / 무통장입금 계좌 / 배송비 정책 / 주문서 안내 문구가 한 번에 세로로 나열됩니다. 어디까지 저장되는지도 안 보입니다.

→ 세그먼트로 3분할 + 하단에 고정 저장 바(변경사항 있음 표시).
빈 상태

빈 화면이 그냥 비어 있다

"아직 주문이 없습니다", "자주 주문한 상품이 없습니다"가 큰 회색 사각형 한가운데 글자만 있습니다. 다음에 뭘 해야 하는지 안 알려줍니다.

→ 빈 상태마다 다음 행동 버튼을 답니다(상품 등록하기 / 상품 둘러보기).
유지

이건 잘 돼 있습니다

상품 코드 체계(JH-FL-001), 단·부쉬 단위, 자주 주문(Quick Reorder) 개념은 도매 업무에 정확히 맞습니다. 구조를 바꾸지 않습니다.

→ 그대로 유지하고 표시만 크고 읽기 쉽게 바꿉니다.
02

개편 원칙 5가지

애매할 때 이 5개로 판단합니다. 원칙끼리 부딪히면 번호가 앞선 쪽이 이깁니다.

#원칙내용
1 이동은 한 곳에서만 화면을 옮기는 건 왼쪽 사이드바뿐입니다. 세그먼트·탭은 지금 화면 안에서 목록을 거르는 용도로만 씁니다. 같은 항목이 두 군데 있으면 하나를 지웁니다.
2 크게, 그리고 덜 빽빽하게 본문 17px, 버튼 56px, 행 높이 76px. 한 화면에 더 많이 넣으려고 크기를 줄이지 않습니다. 안 들어가면 줄이는 게 아니라 나눕니다.
3 상태는 색과 모양 둘 다로 입금 대기·배송 준비·완료·품절은 배지 모양 + 색 + 글자 세 가지로 구분합니다. 색만으로 구분하면 색약인 분과 흑백 출력에서 사라집니다.
4 숫자는 조치로 이어진다 KPI 숫자는 장식이 아닙니다. 0이 아니면 누르면 해당 목록으로 바로 이동합니다. 0이면 회색으로 물러납니다.
5 빈 화면도 일을 시킨다 비어 있는 화면에는 반드시 왜 비었는지 + 다음에 뭘 누르면 되는지를 함께 둡니다.

색은 왜 파랑인가

원티드를 참고하기로 했으니 조작(버튼·링크·선택)은 파랑 #3366FF 하나로 통일합니다. 지금 쓰고 계신 진한 초록은 사이드바(브랜드 자리)로 남깁니다 — 진흥몰이라는 정체성은 지키고, 누르는 것은 전부 파랑으로 배웁니다. 초록을 버튼에 쓰지 않습니다. 초록을 버튼에도 쓰면 "초록이 브랜드인지 버튼인지" 학습이 깨집니다.

04

공통 컴포넌트

이 7개만 만들면 9개 화면은 조립으로 끝납니다. 아래 목업은 진짜로 동작합니다 — 눌러보세요.

4-1. 세그먼트 — 사장님이 말씀하신 "토스 느낌"

회색 트랙 안에서 흰색 알약이 미끄러지는 형태입니다. 화면을 옮기는 게 아니라 지금 보고 있는 목록을 거르는 도구입니다. 개수 배지를 같이 달면 누르기 전에 판단할 수 있습니다.

동작함 눌러서 확인해 보세요 · 키보드 Tab → Enter도 됩니다

4-3. 빈 상태

지금은 "아직 주문이 없습니다" 한 줄뿐입니다. 왜 비었는지 + 다음 행동을 항상 같이 둡니다.

🧾

아직 들어온 주문이 없습니다

고객이 주문하면 여기에 바로 뜹니다. 알림을 켜 두면 새 주문이 들어올 때 소리로 알려드립니다.

05

화면별 개편안 9개

각 화면마다 지금 문제 → 개편 목업 → 개발 지시 순서입니다. 목업은 실제 HTML이라 검사 도구로 뜯어볼 수 있습니다.

나이 배려 — 지켜야 할 10가지

"나이 드신 분들이 쓰실 수도 있어서"가 이 개편의 출발점입니다. 취향이 아니라 규칙으로 못 박습니다.

#규칙기준값 · 이유
1본문 17px 이상지금 13~14px입니다. 노안이 오면 14px 이하는 초점이 안 맞습니다. 설명 글씨도 13.5px 아래로 내리지 않습니다.
2누르는 영역 48px 이상버튼이 시각적으로 작아 보여도 클릭 범위는 48×48px 확보(패딩으로). 손 떨림이 있어도 눌립니다.
3대비 4.5:1 이상회색 위 연회색 글씨 금지. 3-3의 대비표를 그대로 씁니다. #8B968F는 플레이스홀더 전용입니다.
4색만으로 구분 금지상태는 색 + 점 모양 + 글자 세 가지로. 색약인 분과 흑백 출력에서도 읽힙니다.
5라벨은 칸 위에칸 안 회색 글씨를 라벨로 쓰면 입력 시작 순간 사라집니다. 라벨은 항상 칸 바깥 위.
6한 화면에 파랑 버튼 1개가장 하고 싶은 행동 하나만 파랑. 여러 개면 매번 고민이 생깁니다.
7되돌릴 수 없으면 물어본다입금 확인, 삭제, 비밀번호 변경은 확인 창. 문구에 대상과 금액을 그대로 넣습니다.
8결과를 말로 알린다저장하면 "저장했습니다", 담으면 "카라 2단을 담았습니다". 화면이 조용히 바뀌기만 하면 됐는지 모릅니다.
9키보드만으로 다 된다:focus-visible에 3px 파란 외곽선. 지금은 포커스 표시가 없습니다.
10200% 확대에서 안 깨진다브라우저 Ctrl + +로 200%까지 키워도 가로 스크롤이 안 생겨야 합니다. 고정 px 폭 대신 max-width를 씁니다.
확인 방법 — 이 문서 맨 위 글자 크게 버튼을 켠 채로 5번 목업들을 다시 훑어보세요. 글자만 커지고 레이아웃이 무너지지 않으면 통과입니다. 실제 구현에서도 같은 방식으로 점검하세요.

08

작업 순서

위에서부터 순서대로 하면 중간에 되돌아올 일이 없습니다. 1~3번은 하루면 끝나고, 화면이 즉시 달라 보입니다.

  1. 토큰 CSS를 전역에 넣는다3번 블록 복사. 기존 하드코딩된 색·크기를 var(--jh-*)로 바꿉니다. 이것만 해도 글자·버튼이 커집니다.
  2. Pretendard를 서버에 올린다CDN 링크 금지. word-break:keep-all도 같이 겁니다.
  3. 상단 탭 5개를 삭제한다사이드바에 "운영 현황"을 추가하고 판매/설정 두 그룹으로 나눕니다. 이 하나가 가장 큰 변화입니다.
  4. 세그먼트 컴포넌트를 만든다4-1 코드 그대로. 상품 관리·주문 관리·설정·로그인 4곳에서 재사용합니다.
  5. 버튼·입력칸·배지를 컴포넌트로 뽑는다화면마다 따로 만들지 마세요. 나중에 크기를 바꿀 때 한 곳만 고치면 되게 합니다.
  6. 상태를 계산값으로 바꾼다재고 0 → 자동 품절. "0개 · 판매중"이 구조적으로 나올 수 없게 만듭니다.
  7. 고객 이름 ???를 고친다인코딩 확인 → 대체 표시(이메일 앞부분) → "이름 미등록" 배지 순서.
  8. 빈 상태 4곳에 다음 행동을 단다주문 없음 / 자주 주문 없음 / 주문내역 비로그인 / 검색 결과 없음.
  9. 설정을 세그먼트 3분할 + 고정 저장 바로 바꾼다미저장 상태 표시와 미리보기를 함께 넣습니다.
  10. 200% 확대와 키보드만으로 전 화면을 점검한다가로 스크롤이 생기거나 포커스가 안 보이면 6번 규칙 위반입니다.
하지 말아야 할 것 — ① 세그먼트로 화면을 이동시키기(원래 문제로 복귀) ② 초록을 버튼 색으로 쓰기(브랜드/조작 학습이 깨짐) ③ 더 많이 넣으려고 글자·버튼 줄이기(개편의 목적을 정면으로 뒤집음) ④ 상품 코드 체계·단·부쉬 단위 건드리기(업무에 맞게 잘 돼 있습니다).
